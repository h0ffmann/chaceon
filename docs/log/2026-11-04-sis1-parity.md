## Getting ice into `ww3_ts1`

`W3SRCE` calls `W3SIS1` only when `INFLAGS2(4)` (ice was read) and `ICE > 0` (`w3srcemd.F90:2079`), so a plain
`ww3_ts1` never reaches it: the first capture had 0 calls. `ww3_shel.nml` needs `INPUT%FORCING%ICE_CONC='H'`, one
`ICE` homogeneous input and `HOMOG_COUNT%N_ICE=1`. It also needs `ICE_PARAM1='H'` and an `IC1` input, because the
switch has `IC1` and `W3SIC1` stops the run with "ICE PARAMETER 1 REQUIRED BUT NOT SELECTED" otherwise. `capture.sh`
edits the case that way when a variant sets `ice`. The concentration stays below `CICEN = 0.5` (`w3gridmd.F90:2674`):
above it the point is removed from the sea points and nothing is called.

## What each capture is for

`ice`, `ice2` and `icesplit` vary `ICE` and the coefficients (`&SIS1 ISC1, ISC2`). `iceoff` makes `ALPHA` exactly 0
with `ICE > 0`, the second half of the guard of `:191`. The `*poke` variants put `ICE` = 0, -0.5 and NaN, and one bin
= -0.001, NaN, -0, 1 and +Inf, at the routine's entry (`regtests/capture/sis1.py`), because `W3SRCE` never gives them:
it calls only for `ICE > 0`, and WW3's spectra are nonnegative. `iceoffpoke` combines the +Inf bin with `ALPHA = 0`,
the only input where the guard `ALPHA > 0` changes a result (`Inf*0` is NaN).

## Reading the compiled code

`MAX(0.,v)` is `fmaxnm`, as in `W3SBT4`; a NaN gives 0, so `v > 0 ? v : 0`. The scatter is `fmul` then `fdiv`, true
divisions, and the final `S/DTMIN` is a vectorised `fdiv`; no `fmadd`. The port matched on the first try.

## A weak fault, and a fault that needed a poke

`A >= 0` as `A > 0` changes nothing for any input: a zero bin adds a zero. `NaN` in a bin and the `ALPHA > 0` guard are
caught only by pokes, as `W3SIN4`'s floors were. Without `iceoffpoke` the guard would sit in the report as undetected.
