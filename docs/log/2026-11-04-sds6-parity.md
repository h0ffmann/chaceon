## The disassembly decided three things

`__w3src6md_MOD_w3sds6` in the reference shows `MAX(0.,x)` as `fmaxnm` against a zero register, `-1.0*(...)` as `fneg`, and
`NEXDENS**SDS6P1` as one `__powisf2` call per band (the exponents are `INTEGER` in `w3gdatmd.F90:901`). The first kernel
used `MAX` as `y != y || x > y` (the form of `W3SDS3`), which returns `-0` for `MAX(0,-0)` where `fmaxnm` returns `+0`.
It was replaced after reading the disassembly and before the first replay. `MAX(0.,x)` is `x > 0 ? x : 0` now, which is
also what `FMax` needs on SPIR-V. A `-0` reaches the line only with both coefficients negative (`T1` and `T2` are then
`-0`): `aneg` is the only capture that catches a `MAX` that keeps it.

## What the model runs never reach

At `SDSET` false, `ALL(EDENS > EDENSMAX)` is false in every model call: the bands above the peak fall under `1E-5` of the
maximum. Only a poked flat spectrum takes the `ALL` path (100 calls). The lowest band has no excess in any model run, so
`CG(1)`, `WN(1)`, `DSII(1)`, `SIG2(1)` and the `XFAC` at `IK=1` need a spike at the entry (`poke`). The first poke used a
spike of 1.0, which stays under the threshold of the lowest band (about 85 in `EDENS`); 1E6 exceeds it.
`MAX(0,NaN)` in `T1` and `T2` is reached by a NaN `WN` in the poke, `MAX(0,T)` of a negative `T` by a negative `SDSA1`
or `SDSA2` in a namelist.

## Troubles

The scratchpad of the session is shared by parallel agents. Two files with a common name were overwritten by another
agent (`dis.sh` and a SPIR-V log); names carry the routine now. A kernel edited for a fault run would also have reached
a PTX build reading the same tree: the fault runs use a copy of `rust/`.

## Not done

`W3SDS6` is not called from `W3SRCE`. The siblings `W3SPR6`, `W3SIN6`, `W3SWL6` and `W3FLX4` are other ports. Captures
sample one call in two or eight ⚠.
