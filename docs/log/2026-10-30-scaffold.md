# Scaffold, the two compilers read, and float bits against gfortran

2026-10-30, agent session `cd86e8f5` for the owner; no issue. Branch
`goal/cd86e8f5-7342-rust-port-scaffold`.

## Question

Can a pure Rust WW3 on rust-gpu and Rust-CUDA keep ww3-gpu's rules, compared with metocean/WW3 7.14?
And how does Rust represent WW3's `REAL` and `DOUBLE PRECISION`?

## What was done

- Pinned `WW3/` at `92e2cf66`; sized it with `just port-status`: 135 `.F90` files, 252 119 lines.
- Read Rust-CUDA `3a82c35` and rust-gpu `60d1e25` as shallow clones. Neither was built or run ⚠.
- Probed gfortran 14.3.0 (`gcc:14-bookworm`, `--platform linux/amd64` under emulation, `-O3
  -fno-second-underscore -ffree-line-length-none`) against rustc 1.99.1 on the Apple M1 Pro. A
  small program printed the hexadecimal bits of each `REAL` constant of `constants.F90`, and of
  `d=0.1`, `DBLE(1.E-15)`, `d=a*b` and `DBLE(a)*DBLE(b)` with `a=0.1`, `b=3.3`. It stayed outside the
  repository, per ADR-0002.

## Result

- All nine derived constants are identical (v):

  | Name | Bits | Name | Bits |
  |---|---|---|---|
  | `TPI` | `40C90FDB` | `DERA` | `3C8EFA35` |
  | `HPI` | `3FC90FDB` | `RADIUS` | `4AC247EB` |
  | `TPIINV` | `3E22F983` | `G2PI3I` | `382FD8FE` |
  | `HPIINV` | `3F22F983` | `G1PI1I` | `3C84F58A` |
  | `RADE` | `42652EE0` | | |

- The conversions match with `as` at the Fortran's place (v): `d=0.1` is `3FB99999A0000000`,
  `DBLE(1.E-15)` is `3CD203AFA0000000`, `d=a*b` is `3FD51EB860000000`, `DBLE(a)*DBLE(b)` is
  `3FD51EB852147AE0`. Rust's `0.1_f64` is `3FB999999999999A`, not WW3's value.
- Double precision reaches the device in `W3SDB1` and `W3SRCE`; the heaviest kernels have none
  (`just f64-census`).
- Rust-CUDA's builder defaults are `fma_contraction: true`, `override_libm: true`
  (`crates/cuda_builder/src/lib.rs:200-219`); both break parity.
- rust-gpu emits no `NoContraction` (`grep -rn NoContraction crates`: no match). Vulkan then allows
  contraction, and allows 2.5 ULP in `OpFDiv` (Vulkan specification, read 2026-10-30).

## What it changes

Rust-CUDA leads and rust-gpu is judged by tolerance (ADR-0003, ADR-0005). The probe is a `PARAMETER`
fold and four assignments, and it shows nothing about `-O3` in a real kernel.

## Reference build

`just ref-build` passed on the M1 Pro, under amd64 emulation, with no errors: image `d4398f752f75`, 20
`ww3_*` programs, `switch_chaceon_shrd`, gfortran 12.2.0, glibc 2.36 (v, `BUILD_INFO`). `ww3_shel`
starts and prints its banner; it was not run on a case ⚠. Emulation is not a reference machine
(ADR-0005), so this image proves the build, not the bits.

The bit probe above used gfortran 14.3.0, and the reference is 12.2.0. It should be repeated with the
reference's compiler in Batch 0 ⚠.
