## Reading the compiled code first

The module built alone in `gcc:12-bookworm` (gfortran 12.2) with the switch's `-DW3_*` flags and
`-O3 -ffp-contract=off -fdump-tree-optimized` gives the GIMPLE of `w3sin3` without building the model. gfortran folds
`KAPPA**2` and `GRAV**2*TPI`, calls `sincosf` once for `COS(USDIR)` and `SIN(USDIR)`, vectorises the tail's `TEMP` sum
four wide and then adds the lanes in order, and keeps `ZBETA` as `(CONST3*(COSWIND + KAPPA/((ZCN*UST)*CM)))*UCN**2`.
The first replay of the first capture was already 0 differ.

## What the captures reach, and what they cannot

`SWELLF` is 0 by default (`w3gridmd.F90:1710`), so `CONST3 = 0`, `ZBETA = 0` and `D` never goes negative: a swell
variant (`SWELLF=1`) is the only way to run the `STRESSSTABN` branch, and a retuned `SIN3` namelist moves `BETAMAX`,
`SINTHP`, `ZALP` and `ALPHA0` off their defaults. A calm run reaches `IND = 1` and `J = IALPHA-1` by itself and has
`S = 0` everywhere; only an entry poke (`regtests/capture/sin3.py`) reaches `IND = IUSTAR-1` and the two floors. The floors
are dead code in effect: `MAX(UST,1E-5)` and `MAX(USTAR,EPS2)` change no output for any input, as the report shows.

## Not done

A fault on `ZLOG` exactly 0 is not reachable. The `CONST0` of the tail is one number per grid: three regroupings of it
give the same `f32` here, so its order rests on the GIMPLE ⚠. Only `NK = 36`, `NTH = 24` was captured.
